Name

gweb — literate programming for the Go programming language

gtangle, gweave — translate GWEB to Go and/or TeX

Synopsis

gtangle [-o dir] webfile[.w] [changefile[.ch]]
gweave  [-o dir] webfile[.w] [changefile[.ch]]

Description

GWEB is a literate programming system for Go, modeled closely on Donald Knuth and Silvio Levy's CWEB. You write a single .w source file that interleaves TeX documentation with Go code, and two tools read it in opposite directions — exactly as CWEB does for C, with C replaced by Go.

CWEBGWEBpurpose
ctanglegtangleextract compilable source (.go) for the machine
cweavegweaveproduce a typeset document (.tex → PDF) for people

gtangle strips the documentation, reassembles the named code sections in the order the Go compiler needs, runs gofmt(1) on the result, and writes the .go files.

gweave produces a TeX file in which reserved words are bold, identifiers italic, strings typewriter, and named sections linked by number, with a cross-referenced index and list of refinements generated automatically. Declared type names are set bold and const names typewriter; override any of it with @f / @s.

The program and the essay explaining it are not two artifacts kept in sync — they are one file.

Prerequisites

GWEB assumes you already know Go and are comfortable with TeX — in particular plain TeX, since gwebmac.tex is plain TeX, not LaTeX. Beyond that:

  • A TeX distribution (TeX Live or MacTeX), providing the tex, pdftex, and luatex engines.
  • For Korean output, the Noto Serif/Sans CJK KR fonts — kotexgweb.tex selects them by name.

Installation

gtangle installs the Go way, since its sources are committed:

go install github.com/sjnam/gweb/cmd/gtangle@latest

gweave is generated rather than committed — as in CWEB, only the Go needed to bootstrap the tangler is in the repository — so install both from a checkout:

git clone https://github.com/sjnam/gweb && cd gweb
make build                # bin/gtangle and bin/gweave
make test                 # the test suite
./install.sh              # commands + gwebmac.tex + man page

Build through make, not a bare go build ./..., on a fresh checkout: make builds gtangle from the committed sources, runs it to tangle the rest, then builds gweave. The installer takes --prefix, --bindir, --mandir, --texmf, and --uninstall.

Usage

gtangle foo.w     # -> foo.go  (plus any @(file@>= outputs)
gweave  foo.w     # -> foo.tex
pdftex  foo.tex   # -> foo.pdf (gwebmac.tex must be on TEXINPUTS)

The .w extension may be omitted, as in CWEB — gtangle foo reads foo.w, and a bare change-file name gets .ch. Each command prints a brief cweb-style progress line, one *N per starred (chapter) section.

A second argument is a change file, which patches the master source without editing it (CWEB's .ch mechanism):

gtangle examples/wc.w examples/wc.ch   # a CSV variant of wc

For a hyperlinked PDF you may also go through DVI, exactly as CWEB does — request the \special{pdf:…} back end with \let\pdf+, then convert:

tex "\let\pdf+ \input foo.tex"   # -> foo.dvi (with pdf: specials)
dvipdfmx foo.dvi                 # -> foo.pdf (links + bookmarks)

The tangled Go always carries //line directives, so the compiler, go vet, and panic traces report errors at .w positions instead of .go ones — the Go counterpart of CWEB's #line:

gtangle foo.w && go build .      # an error reads  foo.w:42: ...

Options

-o dir
Write output files to dir instead of the input file's directory. For gtangle, the directory — and any subdirectories named by @(file@>= targets — is created if necessary.
-version
Print the version and exit.

Example

A fragment of examples/seq.w, a tiny lazy-sequence library. Prose is TeX, code is Go, and @<…@> names a section that is spliced in elsewhere:

\def\title{Lazy Sequences in Go}

@s Seq int

@* Introduction.
This example builds a tiny library of {\it lazy sequences\/} and uses it to
print the first few even Fibonacci numbers. A sequence here is an
|iter.Seq[V]|, which is just the function type |func(yield func(V) bool)|:
a {\it producer\/} that hands each value to a |yield| callback and stops
early if |yield| returns |false|.
@c
package main

import (
	"fmt"
	"iter"
)

@<The Fibonacci generator@>
@<The |Map| combinator@>

func main() {
	@<Print the first even Fibonacci numbers@>
}

@* A sequence is a closure.
The Fibonacci numbers are an infinite sequence, so they could never be
returned as a slice; as a lazy |iter.Seq[int]| they are no trouble at all.
@<The Fibonacci generator@>=
func fibs() iter.Seq[int] {
	return func(yield func(int) bool) {
		a, b := 0, 1
		for yield(a) {
			a, b = b, a+b
		}
	}
}

gtangle seq.w yields a gofmt-clean seq.go; gweave seq.w yields seq.tex, which typesets into a cross-referenced document with an index and a list of the section names.

Control codes

Structural codes, which begin a part of the web:

@  @\t @\nbegin a normal (unstarred) section
@*begin a starred section (group/chapter); the title runs to the first .
@*Nbegin a starred section at depth N (@*0 == @*)
@c, @pbegin the code part of an unnamed section
@<name@>=begin the code part of a named section (a "refinement")
@(file@>=begin code that gtangle writes to file
@i fileinclude another .w file at this point

In-code codes:

@<name@>reference to a named section — expanded by tangle, linked by weave
@=text@>verbatim text passed literally to the tangled Go
@t text@>TeX text inserted into the woven code (ignored by tangle)
@&paste: join the surrounding tokens with no space
@@a literal @

Layout and index codes, read by gweave and ignored by gtangle:

@,insert a thin space
@/force a line break, continuing at the same indentation
@|an optional line break — a place a long line may wrap
@#a line break followed by a blank line
@f a bformat identifier a like identifier or keyword b
@s a blike @f, but omit the entry from the index
@!index the next identifier as a definition (underline it)
@^text@>index entry, typeset in roman
@.text@>index entry, typeset in typewriter
@:text@>index entry, typeset by the user macro \9
@%the rest of the line is a comment in the .w file
@q text@>quoted material — a comment for the web author

Inline code inside prose is written between vertical bars, as |identifier|. Section names may be abbreviated with a trailing ... once the full name has appeared. The full reference is in format.md.

Notes specific to Go

  • Go has no preprocessor, so @d never tangles to code — gtangle ignores it. gweave, however, reads @d Name as a request to set Name in typewriter, like a CWEB macro; useful for constants you do not declare in this web, e.g. @d http.StatusOK.
  • gweave classifies declared names automatically: a type name is set bold, like a predeclared type, and a const name is set in typewriter — the treatment cweave gives names defined by @d, since a Go const is the closest analogue. Both the single and parenthesized-block declaration forms are recognized.
  • @f MyType int sets a user type in bold; @f Name x overrides the automatic classification back to plain italic. These apply globally and may appear in limbo or in a section's definition part.
  • The default tangled output is basename.go; additional files come from @(file@>=, so one web can emit several files — including a go.mod or a _test.go.

Localization

The woven output can be written in Korean by processing it with luatex rather than pdftex and putting one line in the .w file's limbo:

\input kotexgweb

kotexgweb.tex loads luatexko, selects the Noto Serif/Sans CJK KR fonts, translates gweave's fixed wording into Korean, and supplies a LuaTeX PDF back end so that blue cross-reference links and the bookmark pane work with Korean titles.

gweave needs no flag for this. All the human-readable text it emits goes through macros — \GU, \GNused, \Gsectionword, … — that kotexgweb.tex overrides, so the same mechanism localizes to any language: write your own \input file modelled on it.

Files

gwebmac.tex
The TeX macros \input in the first line of every gweave output file — the analogue of CWEB's cwebmac.tex. gweave supplies that line itself, so the .w file need not.
kotexgweb.tex
Korean localization: fonts, wording, and the LuaTeX PDF back end.
gwebman.tex
The GWEB user manual (make manual), together with the .w file-format reference in format.md.
gweb.1
The man page for both commands. After ./install.sh, man gtangle and man gweave describe them.
TEXINPUTS
Point this at a directory holding gwebmac.tex, or copy the file next to your document. The installer places it in your TeX tree, so this is not normally needed. See tex(1) for the details of the searching.

Design notes and limitations

  • Lexing for free. Tangle relies on gofmt (go/format) to canonicalize the assembled program, so the emitted Go is always tidily formatted as long as the web assembles into valid Go.
  • Pretty-printing by mirroring. gweave mirrors the source's own spacing rather than re-deriving layout from a full Go grammar the way cweave does for C. Because gofmt-formatted Go already encodes the grammar in its spacing, mirroring it reproduces gofmt exactly — including the tricky cases (*T vs a * b, []T vs a[i], precedence spacing like a*b + c) — without any parsing. Write the code in your sections in gofmt style for the best-looking output.
  • Definition detection in the index is heuristic — an identifier following func/var/const/type, or just left of := — not a full type check.
  • Diagnostics. Both tools report, with file:line locations, unterminated control codes, references to undefined sections, ambiguous ... abbreviations, and named sections defined but never used. These are warnings; gtangle still stops if it must actually expand an undefined reference. An origin map kept in step through @i includes and change-file edits makes every location point back to the file and line you actually wrote.
  • Page layout follows cweave. gwebmac.tex gives the woven document the same furniture CWEB produces: run-in bold section headings with a page break before each starred section, §sec JOBNAME … GROUPTITLE page running heads, a two-column index under your own @* Index. section, a Names of the Sections list, and a contents page with dotted leaders. As in CWEB, the contents page is produced at the end in a single TeX pass; move it to the front when binding if you prefer.
  • Hyperlinks and bookmarks. Every section number shown as a reference, in the index, or on the contents page is a blue link to that section. Starred sections also become a PDF outline, nested by their @*, @*1, @*2 depths. pdftex and luatex in PDF mode use the engine's own primitives; the DVI route emits \special{pdf:…} for dvipdfmx when you ask with \let\pdf+. With a plain DVI engine and no \let\pdf+, links and bookmarks are simply omitted.
  • Self-hosting. GWEB tangles its own sources the same way, so editing a .w reshuffles the line numbers in the bootstrap Go it commits — the price of keeping the generated code honest about its literate origin.

Authors

Don Knuth wrote WEB for TeX and Pascal. Silvio Levy designed and developed CWEB by adapting the WEB conventions to C; Knuth began using CWEB and made further refinements.

GWEB adapts those conventions to Go and is maintained by sjnam.
