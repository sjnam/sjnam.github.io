Name

gweb — literate programming for Go

Synopsis

foo.w  --[ gtangle ]-->  foo.go                     for the machine
foo.w  --[ gweave  ]-->  foo.tex  -->  foo.pdf     for people

One source file. Two readings of it.

Description

GWEB is a literate programming system for Go, modeled closely on Donald Knuth and Silvio Levy's CWEB.

The premise, which is Knuth's, is that a program is a piece of writing addressed to human beings, and only incidentally something a compiler consumes. So you do not write a program and then document it. You write one .w file — a web — in which TeX prose and Go code are the same document, ordered the way the idea unfolds rather than the way the compiler demands. Then two tools read that file in opposite directions:

gtangleextracts the compilable .go, reassembling the sections in the order Go needs, and runs gofmt(1) over the result
gweaveproduces a typeset .tex document — bold keywords, italic identifiers, sections linked by number, index and cross-references gathered automatically

The program and the essay explaining it are not two artifacts kept in sync — they are one file. That is the whole of the idea; everything else is machinery in service of it.

GWEB is CWEB with C replaced by Go, deliberately and almost line for line: gtangle is the analogue of ctangle(1), gweave of cweave(1), and gwebmac.tex of cwebmac.tex. If you have read a woven CWEB document, you already know how to read a woven GWEB one.

Example

Here is what a web actually looks like — the opening of examples/seq.w, a tiny lazy-sequence library. Prose is TeX, code is Go, and @<…@> names a chunk that is written out and explained somewhere else:

@* Introduction.
This example builds a tiny library of {\it lazy sequences\/} and uses it to
print the first few even Fibonacci numbers. A sequence here is an
|iter.Seq[V]|, which is just the function type |func(yield func(V) bool)|:
a {\it producer\/} that hands each value to a |yield| callback and stops
early if |yield| returns |false|.
@c
package main

import (
	"fmt"
	"iter"
)

@<The Fibonacci generator@>
@<The |Map| combinator@>

func main() {
	@<Print the first even Fibonacci numbers@>
}

@* A sequence is a closure.
The Fibonacci numbers are an infinite sequence, so they could never be
returned as a slice; as a lazy |iter.Seq[int]| they are no trouble at all.
@<The Fibonacci generator@>=
func fibs() iter.Seq[int] {
	return func(yield func(int) bool) {
		a, b := 0, 1
		for yield(a) {
			a, b = b, a+b
		}
	}
}

Notice that main is written before the things it calls exist, and that each section is introduced by the paragraph that motivates it. The order is the order of explanation. gtangle puts it back into the order Go wants; you never have to think about that order while writing.

The result is a gofmt-clean seq.go on one side, and on the other a PDF with an index, a list of section names, and every cross-reference hyperlinked. The PDF is the side meant for human eyes.

Notes

A few things about GWEB that may not be obvious:

  • Lexing comes for free. Tangle hands the assembled program to gofmt (go/format), so the emitted Go is canonically formatted as long as the web assembles into valid Go at all.
  • Weave mirrors gofmt instead of parsing Go. Where cweave re-derives C's layout from a grammar, gweave simply mirrors the source's own spacing — and because gofmt-formatted Go already encodes the grammar in that spacing, mirroring reproduces gofmt exactly, down to the tricky cases (*T vs a * b, []T vs a[i], precedence spacing like a*b + c) without any parsing at all.
  • Errors point at the .w, not the .go. The tangled output always carries //line directives, so the compiler, go vet, and panic traces all report positions in the file you actually wrote — the Go counterpart of CWEB's #line.
  • The PDF is navigable. Every section number in the text, the index, or the contents page is a link, and starred sections become a PDF outline nested by depth.
  • It documents itself. GWEB is written in GWEB: only the Go needed to bootstrap gtangle is committed, and the rest — including all of gweave — is tangled from its own .w sources on the way to building.

Other languages

A web can be written in Korean — or any language — by adding one line to the .w file's limbo and typesetting with luatex:

\input kotexgweb

gweave needs no flag for this. Every piece of human-readable text it emits goes through a macro — \GU, \GNused, \Gsectionword, … — so an \input file that redefines them localizes the whole document, headings, index, bookmarks and all. kotexgweb.tex is the worked example: it loads luatexko, selects the Noto Serif/Sans CJK KR fonts, and supplies a LuaTeX PDF back end so links and the bookmark pane work with Korean titles. Most of the recent examples below are Korean essays.

Authors

Don Knuth wrote WEB for TeX and Pascal. Silvio Levy designed and developed CWEB by adapting the WEB conventions to C; Knuth began using CWEB and made further refinements.

GWEB adapts those conventions to Go and is maintained by sjnam.
